# 仕様書（v1）

見た目・動き・文言の正解は `mock/index.html`。この文書は「モックを本番化するときに守るルール」と「モックにないもの」を定義する。

## 1. 構成
- タブ5つ：ホーム / ロードマップ / れんしゅう / 弱点 / 単語帳（モックのまま）
- クイズは全画面オーバーレイ、週間レポートは全画面オーバーレイ、詳細はボトムシート
- 追加画面（モックにない）：**ログイン画面**、**子どもの名前入力（初回のみ）**

## 2. 用語・コード
| 項目 | 値 |
|---|---|
| 級コード（DB） | `5` `4` `3` `p2`(準2級) `2` `p1`(準1級)。モックの数値 25/15 は p2/p1 に対応 |
| 級の順序 | 5 → 4 → 3 → p2 → 2 → p1 |
| 種類 `type` | `word`(単語) `phrase`(熟語) `idiom`(イディオム・会話表現) |
| 問題の形 `mode` | `en2ja`(英→和) `ja2en`(和→英) `spell`(スペル)。**聞き取りは無い** |
| テーマ `theme` | たべもの / どうぶつ / がっこう / ばしょ / いろ・ようす / うごき / きもち / かいわ（語彙追加で増えてよい。弱点マップの行はDBの theme から動的に作る） |

## 3. ルール（モックの挙動そのまま）
**累計集計**：語ごと・形ごとに `seen`（出題数）と `correct`（正解数）。DB の `item_stats` が正。語の合計 = 3形式の合計。

**級クリア**（`GATE=0.9`, `MINSEEN=3`）
- その級の**全語**が合計3回以上出題済み **かつ** 級全体の正答率（全語・全形式の合計）≥ 90%
- 下の級から順に判定。一度クリアしたら戻らない（`level_progress`）。判定は DB の `submit_session` 内（`sync_level_progress`）
- 解放：クリア済みの級 ＋ 最初の未クリア級（= 現在の級）。それより上は🔒。練習・クイズに出るのは解放済みの級だけ

**おぼえた語**：合計3回以上 かつ 正答率80%以上（ホームの級別バー用）

**ステージ**（ロードマップ）：級の中のテーマ別。ステージクリア表示＝そのテーマの全語が3回以上 かつ 正答率90%以上。タップでそのテーマだけ10問

**出題**
- 問題数 5/10/20。出し方：苦手をおおめに（既定）/ ぜんぶ同じ / まだやってない語
- 重み付き非復元抽出。語の重み＝未出題 1.6、出題済み `1 + 3 × (1 − 正答率)`
- ミックス時の形の選び方：語ごとに 形の重み＝未実施 0.6、実施済み `(1 − 正答率) + 0.25`。`spell` は英語表記が24文字を超える語では出さない
- 選択肢：同じ `type` の別語から3つ（同じ級を優先）＋正解。`en2ja` は日本語、`ja2en` は英語を選ぶ
- スペルは**並び替え**（入力しない）：英語表記が1語なら文字タイル、空白で区切られた2語以上（熟語・イディオム）なら単語タイル。タイルはシャッフル（元の並びと同じにしない）。タップで上の枠に入れ、枠のタイルをタップで戻す。全部入れると「こたえる」が押せる
- スペル判定：並べた結果を小文字化 → `a-z0-9` と空白以外を除去 → 連続空白を1つに → 正解と完全一致（ハイフン・記号は無視）。モード名 `spell` とDBの記録は変えない

**弱点マップ**
- ヒートマップ：テーマ（行）× 形（列）。セルは累計 ≥3 回で正答率を表示、未満は「–」（灰）
- 色：`hue = 4 + 正答率 × 126`（赤→黄→緑）。彩度/明度は固定トークン
- 「いちばん苦手」：累計 ≥6 回のセルのうち正答率が最小。ホームのヒーローと弱点タブの見出しに使う
- 級フィルタ（ぜんぶ/各級）。セルをタップ → 中の語リスト → 「このマスを れんしゅう」

## 4. 画面ごとの要点
- **ホーム**：ヒーロー（いちばん苦手→10問）／いまの級カード／週間レポートカード／今日の問題数・連続日数・おぼえた語／級別「おぼえた」バー／さいきん まちがえた語3つ
- **ロードマップ**：縦の道（上=準1級ゴール、下=5級スタート）。クリア済み・挑戦中・🔒。挑戦中カードは正答率メーター（90%の線）と「3回以上こたえた語 x/n」「クリアまで：…」
- **れんしゅう**：級（解放済みのみ）・種類・形・出し方・問題数
- **弱点**：ヒートマップ／AIコーチの分析（Phase 2）／形別・種類別／苦手ワード ワースト5
- **単語帳**：級・種類フィルタ、語ごとに3形式の出来ぐあいの線。🔒の級は練習不可
- **結果画面**：スコア・まちがえた語・級クリア時のバナー（`submit_session` の `newly_cleared`）

## 5. AI分析（Phase 2）
- 呼び出し：`supabase.functions.invoke('ai-analysis', { body: { child_id, summary } })`
- `summary` = モックの `buildSummary(lv)` の戻り値（scope, cells, modes, types, levels, worstWords）。`levels` には `status`（クリア済み/挑戦中/未解放）を含める
- プロンプトは `supabase/functions/_shared/prompts.ts`（モックの `aiPrompt` と同一）。出力JSONのスキーマ：`headline, summary, weaknesses[{theme,mode,finding,tip}], strengths[], plan[{theme,mode,reason}], childMessage`
- 表示：モックの `aiCard()` と同じ。`plan` のボタンは `practiceCell(theme, mode, level)` を開く。分析後に練習したら「最新の結果で分析しなおせます」を出す
- 1日20回まで（Edge Function 側）。`rate_limited` は「しばらくしてから」と表示

## 6. 週間レポート（Phase 2 メール / Phase 3 LINE）
- 設定：送り先（メール／LINE、両方可）・曜日・時刻（JST, 6〜22時）・オン/オフ。メールの初期値は空（ログインは偽メールのため。保護者の実メールを入力してもらう）
- **自動送信**：pg_cron が毎時 `send-weekly-report`（mode=cron）を呼ぶ → 設定の曜日・時刻に一致する人へ。6日以内に自動送信済みならスキップ
- **今すぐ送信**：`invoke('send-weekly-report', { body:{ child_id } })`。1日3回まで。結果は `report_logs` に残り、画面の「最近の送信」に出す
- 内容：直近7日の 学習日数/問題数/学習時間/正答率（先週比）、毎日の問題数、形別正答率、いまの級、いま気になるところ、AIコメント（失敗しても送る）
- 集計は SQL（`weekly_summary` / `weak_overview`）。**学習時間 = クイズ1回の所要秒（上限30分）の合計**
- LINE：公式アカウントの Messaging API（push）。連携は「連携コード」方式（`create_line_code` → ユーザーがトークに6桁を送る → `line-webhook` が紐づけ）

## 8. モック → 本番の置き換え表
| モック（localStorage / artifact 専用） | 本番 |
|---|---|
| `RAW` / `D`（語彙のハードコード） | `vocab_items` を起動時に全件取得（`active=true`） |
| `S.stats`（語×形の s/c） | `item_stats`（読み取り）。書き込みは `submit_session` のみ |
| `S.sessions` / `S.today` / `streak()` | `study_sessions`（今日の合計・連続日数は JST で集計） |
| `S.cleared` | `level_progress` |
| `S.recent`（まちがえた語） | `answer_logs` で `correct=false` を新しい順に取得し語で重複除去 |
| `S.report` / `S.unlockAll` | `report_settings` ／ `unlockAll` は**削除**（モック専用のデバッグ） |
| `seed()` / デモデータ・「デモデータに戻す」 | **削除** |
| `SAMPLE`（`claude.use('sample')`） | `supabase.functions.invoke('ai-analysis' / 'send-weekly-report')` |
| `記録 record()` | クイズ中は配列にためて、終了時（途中終了も1問以上あれば）に `rpc('submit_session', { p_child, p_started, p_answers })` を1回呼ぶ |
| 「テスト送信/今すぐ送信」のモック挙動 | Edge Function 呼び出し |
| LINE 連携の「連携したことにする」 | `rpc('create_line_code')` で発行 → 連携済みは `report_settings.line_user_id` の有無で判定（画面を開き直す/ポーリングで反映） |

**起動時のデータ読み込み**（ログイン後）：`children`（最初の1人。なければ名前入力→insert）→ `vocab_items`・`item_stats`・`level_progress`・`report_settings`（なければ初期行を insert）→ 直近60日の `study_sessions`（連続日数・今日の問題数）。クイズ終了後は `item_stats` と `level_progress` を再取得して画面を更新。

## 9. 認証
- Supabase Auth の**メール/パスワード認証**を「ログインID＋PIN（6桁以上）」として使う。メールは送らない（メールOTPは、カスタム SMTP なしでテンプレートを編集できないため見送り。iOS のホーム画面アプリではマジックリンクだと Safari 側で開いてセッションが分かれるため、それも使わない）
- ログインID は半角英小文字・数字（3〜20字）。内部で `<id>@eitan-radar.invalid` を作って `email` に使う。新規は `signUp({ email, password })`、2回目以降は `signInWithPassword({ email, password })`。セッションは永続化（`persistSession:true`）。Supabase が偽メールの形式を受け付けるか、Phase 1 の最初に確認する
- Supabase 側：「Confirm email」オフ、匿名サインインはオフ（`docs/setup.md`）
- ID は同じプロジェクト内で一意。PIN を忘れても再設定はできない（新しい ID で作り直す）
- 週間レポートの宛先は、ログインメールではなく `report_settings.email` に保護者の実メールを入れる

## 10. 非機能・セキュリティ
- 子どもの学習データと保護者のメールアドレスを保存する。RLS で保護者本人の行だけ読み書き可。`anon` ロールには何も許可しない
- AI へ送るのは集計値と語のみ（氏名・メールは送らない）。レポート本文の「お子さまの名前」はメール/LINE 本文にのみ使う
- 配信停止：アプリの設定でオフ（メール本文の末尾に記載）
- 1日の上限：AI分析 20回/日、今すぐ送信 3回/日

## 11. 受け入れ条件
**Phase 1**：①ログイン→名前入力→ホームが出る ②10問クイズ（3形式）を解くと弱点マップ・単語帳の線・おぼえた語が更新 ③5級を条件達成でクリア→4級解放・結果画面にバナー ④ロック中の級は練習不可 ⑤機内モードでも画面は開く（データ取得はエラー表示でよい）⑥iPhone のホーム画面から全画面で起動、安全領域が崩れない ⑦別の保護者アカウントのデータが見えない（RLS）
**Phase 2**：①弱点タブでAI分析が表示される ②「今すぐ送信」でメールが届く（HTML表示が崩れない）③設定の曜日・時刻に自動で届く（二重送信なし）④AI失敗時もレポートは届く
**Phase 3**：①連携コードで LINE が紐づく ②LINE にレポートが届く ③コードの期限切れ・誤りで案内が返る
