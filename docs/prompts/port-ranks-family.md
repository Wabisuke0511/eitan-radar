# 他アプリへの移植プロンプト：ランク・賞金・家族ランキング

えいたんレーダー（2026-10-12 実装）の「ランクと賞金」「家族ランキング」を、別のアプリ（例：計算道場）に入れるときに、そのアプリの Claude Code に貼るプロンプト。

```
このアプリ（計算道場）に、子どものやる気を上げる「ランクと賞金」と「家族ランキング」を追加したい。
まず CLAUDE.md・README・主要なコード（画面・データ保存・認証・DB スキーマ）を読み、いまの作りを把握してから、下の「先に確認すること」を A/B で私に質問してください。答えが出るまでコードは書かないこと。

【参考：えいたんレーダーでの実装（英単語アプリ）】
- ランクは「レベル（英検の級）を1つクリアするたびに1段」。7段：ウッド冒険者🐣 → カッパー冒険者🐥 → ブロンズ冒険者🦊 → アイアン冒険者🐺 → シルバー冒険者🦁 → ゴールド冒険者🐲 → プラチナ冒険者🦄（スタートはウッド）
- 賞金は「1〜3段目は各1,000円、4段目からは500円ずつ上がる」（カッパー1,000・ブロンズ1,000・アイアン1,000・シルバー1,500・ゴールド2,000・プラチナ2,500円、合計9,000円）。ウッドは0円。式：n ≤ 3 なら 1,000円、それ以外は 1,000 +（n − 3）× 500円
- キャラクターは絵文字を、ランク色のメダル（丸・グラデーション・二重の縁）の中に表示。外部画像は使わない
- 表示する場所：①ホームの「いまのランク」カード（キャラ・ランク名・次のランクの条件と賞金・まだもらっていない賞金の合計）②ランク一覧（全ランクを上から並べ、達成済みは「🎁 わたす」ボタン、受け取り済みは「✓ もらった＋日付」と「取消」、未達成は🔒）③レベルをクリアした瞬間の結果画面に「ランクアップ！ ○○になった！ 🎁 賞金 ○円。おうちの人にもらおう！」
- 賞金の受け渡しは DB に記録する（テーブル例：reward_payments(child_id, rank 1..N, amount, paid_at, PK(child_id, rank))）。記録・取消には保護者の PIN（ログインのパスワードで再認証）が必要。子どもが勝手に押せないようにする
- 不正防止：まだ達成していないランクは DB 側（RLS の with check など）でも記録できないようにする。amount は check 制約で上の式（case when rank <= 3 then 1000 else 1000 + (rank - 3) * 500 end）に固定し、アプリ側の計算と必ず同じ式にする。update はさせない（記録と取消だけ）
- 家族ランキング：1つの保護者アカウントに子どもを複数登録し、ホームの「👤 名前 ▾」で切り替え・追加。子どもが2人以上ならホームに「🏆 家族ランキング（○○の数）」を表示（1位👑・2位🥈・3位🥉、いまの子に「いま」タグ）。選んだ子は端末に記憶。他の家庭のデータは見せない（RLS で保護者本人の子どもだけ）
- 成績・未送信の結果・賞金・設定は子どもごとに分ける

【先に確認すること（A/B で質問）】
1. このアプリの「レベル（ランクが上がる単位）」は何か。例：A 段位・級のクリアごと／B 単元（たし算・ひき算…）のクリアごと／C 正解数やポイントの累計。段数が7でない場合、ランク名をどう割り当てるか（増える・減る場合の案も出す）
2. 家族ランキングで競う数値は何か。例：A 正解した問題の累計／B クリアしたレベル数／C 今週の正解数（毎週リセット）
3. いまのアプリが 1アカウント＝子ども1人の作りなら、子どもを複数にするための変更（スキーマ・画面）をどうするか
4. データ保存の方式（Supabase などの DB／端末の localStorage のみ）。DB がない場合、賞金の記録と PIN の確認をどう実現するか（例：端末内に保存し、保護者用 PIN を別に設定）
5. 賞金額（1〜3段目は各1,000円、4段目から+500円ずつ）と段数で問題ないか。段数が7でない場合も同じ式で各段の金額と合計額を一覧にして確認する

【守ること】
- 既存のデザイン・配色・文言のトーンに合わせる。全面書き換えはしない
- DB を変える場合は新しいマイグレーションを追加し、既存のマイグレーションは書き換えない。RLS は必須
- 秘密情報（service_role キーなど）はコードに書かない
- Supabase を他のアプリ（えいたんレーダー・bpulse-check）と共用している場合は、テーブル名・関数名・ジョブ名に接頭辞を付けて衝突を避け、public 全体を対象にする revoke / grant / drop は書かない（えいたんレーダーはすでに reward_payments・children などを使っている）
- 実装後、ロジック（ランク計算・未受け取り額・ランキングの順位・切り替え）を自分でテストし、結果を報告。iPhone で確認してほしい項目を最後に挙げる
```
